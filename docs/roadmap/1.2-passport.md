# 1.2 — Passport

*Released as 1.2.0 on 2026-11-18. As built:*

- *Packages 1–4 and 6 as planned. Instead of a `PlayContext` on every play call, the player reports each song with its
  Apple Music album ID, which catalog.json maps to a Crate record; that covers the same cases with no call-site
  changes. A record is heard at 60% of the tracks catalog.json counts for it.*
- *Flags carry their own date (`{on, at, how}`) rather than one `cleared` tombstone per mark, so Heard and Saved merge
  separately. Unknown keys from a newer version don't survive yet; add that with the first new key.*
- *Package 5 is half done: `PassportSync` (iCloud key-value storage) is in both apps and turns itself on when the app
  has the entitlement, but no build has the entitlement yet, because it needs the iCloud capability on the App ID
  first and a Mac Developer ID profile. To finish it:*
  1. *Developer portal → Identifiers → io.github.davidlago.JazzDiscovery → enable iCloud (key-value storage is
     included).*
  2. *Make a **Developer ID** provisioning profile for that App ID, and store it base64-encoded as the
     `MAC_PROVISIONING_PROFILE` secret; regenerate the App Store profile (`scripts/provisioning-profiles.swift`).*
  3. *Add `com.apple.developer.ubiquity-kvstore-identifier = $(TeamIdentifierPrefix)$(CFBundleIdentifier)` to both
     targets' entitlements, with `build-app.sh` embedding the profile as Music Library's does, gated on an `ICLOUD`
     repository variable so builds keep working until then.*
- *Era stamps use a short `stamp` name from jazz.json where the full one is long ("Latin & Bossa").*

The app remembers nothing about you except your settings. This release adds a listening passport: what you've heard and
saved, how far into each era you are, and what to play next.

## What people get

- **Heard and Saved** on every record. Heard is marked for you when you play a record through, or by hand.
- **Stamps**: one per era, inked in the era's colour, filling in as you hear its records. A full set is the app's
  quiet long-term goal.
- **Progress where you browse**: a small stamp on heard covers, "4 of 9 records" on era pages, the next unheard stop
  on Start Here.
- **Three doors** at the end of every album page, and when an album finishes playing: *Same room* (shares the most
  players), *What happened next* (the style that answered this one), *An echo today* (a living artist in the same
  line). Each prefers something you haven't heard.
- **The Passport page**: your stamps, a decade strip showing where you've been, instruments you've heard most, recent
  listening, and your saved records and artists.
- **Sync** between your Mac and iPhone through your own iCloud.
- **Import from Last.fm** (if connected): mark as heard the Crate records you've already scrobbled.

## What counts as heard

| State | How |
|---|---|
| **Sampled** | You played at least one 30-second preview from the record. Shown as an outlined stamp. |
| **Heard** | With full tracks: at least 60% of the album's tracks each passed the same threshold the app already uses for scrobbling (half the track, or 4 minutes). Or you marked it yourself. |

Without a subscription nobody can "hear" an album in the app, so *Mark as Heard* is always one tap (you may know the
record from elsewhere), and sampled still moves the stamps a little: an era's stamp fills by heard records, and shows a
dotted outline once anything in it is sampled.

Unmarking is always possible, including for records marked automatically.

## Data

No new bundled data except one optional field on eras, used by the second door:

```json
{ "id": "bebop", "leadsTo": ["cool", "hard-bop"], … }
```

`leadsTo` is curated for all 14 eras (a reaction, a branch or an heir; one to three each). The validator checks the IDs
and that no era lists itself.

## Shared code

### `Shared/Services/Passport.swift`

```swift
@MainActor @Observable
final class Passport {
    struct Mark: Codable, Equatable { var heard: Date?; var sampled: Date?; var saved: Date?; var cleared: Date? }

    private(set) var albums: [String: Mark]        // by album ID
    private(set) var artists: [String: Mark]       // saved only
    private(set) var tracks: [Int: Date]           // Apple Music song ID → when it counted (capped at the last 2,000)

    func isHeard(_ album: Album) -> Bool
    func isSaved(_ album: Album) -> Bool
    func setHeard(_ album: Album, _ on: Bool)
    func toggleSaved(_ album: Album)
    func progress(inEra id: String, library: JazzLibrary) -> (heard: Int, sampled: Int, total: Int)
    func recent(limit: Int) -> [Entry]

    func listened(_ event: ListenEvent)            // from the player
}
```

Storage is one JSON file in Application Support (not Caches, where `DiskCache` lives, because this must survive a
cleanup), written atomically after each change.

Later releases add their own sections to the same store (path progress, versions of a tune heard, blindfold scores),
each as a new optional key.

### Sync

`NSUbiquitousKeyValueStore`, one key holding the same JSON, compressed. It's far inside the limits (1 MB) even with
every record marked.

Merging is per item, per field, latest date wins; `cleared` is a tombstone so un-marking on one device isn't undone by
the other. The merge is a pure function with tests. On launch and on the store's change notification the app merges
and writes back only if something changed.

Signing work, which is the real cost of sync:

- Both targets need the entitlement `com.apple.developer.ubiquity-kvstore-identifier` =
  `$(TeamIdentifierPrefix)$(CFBundleIdentifier)`. The Mac and iPhone apps already share a bundle ID, so they share the
  store with no extra setup. The iPhone target has no entitlements file today; it gets one.
- **You**: turn on iCloud (key-value storage) for `io.github.davidlago.JazzDiscovery` in the developer portal.
- **iPhone**: `scripts/provisioning-profiles.swift` recreates the App Store profile so it carries the capability.
- **Mac**: release builds are signed with the Developer ID certificate and *no* provisioning profile
  (`PROVISIONING_PROFILE_SPECIFIER=""` in `scripts/build-app.sh`). iCloud is a restricted entitlement, so the Mac
  build needs a Developer ID provisioning profile embedded. **Music Library already does this** and ships it
  (`/Users/davidlago/Develop/devin-tests/music-library`: `docs/distribution.md` § "iCloud (optional)",
  `scripts/build-app.sh`, `.github/workflows/ci.yml`), so copy its pattern:
  - You make a **Developer ID** profile in the portal for the App ID with iCloud, and download it.
  - `build-app.sh` takes `PROVISIONING_PROFILE=…`: it reads the profile (`security cms -D`), fails clearly if the
    profile doesn't allow the entitlement, embeds it as `Contents/embedded.provisionprofile` and signs with an
    entitlements file that adds iCloud. Without a profile it builds exactly as today.
  - CI stores it as a `MAC_PROVISIONING_PROFILE` secret and installs it only on tags.
  - The iPhone build gets the entitlements file only when a repository variable (`ICLOUD=1`) says the App ID is ready,
    so CI keeps passing before you've done the portal step.

  Jazz Discovery has it easier than Music Library did: its Mac app already uses the registered bundle ID
  `io.github.davidlago.JazzDiscovery`, so there's no bundle-ID switch and no settings to import. Music Library uses an
  iCloud *container* (iCloud Documents); the passport only needs key-value storage, which is the same iCloud
  capability on the App ID with a different entitlement (`com.apple.developer.ubiquity-kvstore-identifier`), so the
  build script's check looks for that key instead. Ad-hoc CI builds on pull requests can't carry the entitlement and
  build without it, as Music Library's do.

If the Mac signing turns out harder than expected anyway, 1.2 ships with the passport local on the Mac and synced on
iPhone only, and sync on the Mac follows in 1.2.1. Nothing else depends on it.

### Player

`Shared/Services/Player.swift`

- `enum PlayContext { case album(String), era(String), artist(String), search }` (later releases add cases). Every
  public `play…` method takes one; the views already know it.
- The player keeps its own per-track listening measure. `tick()` already computes real listening time and passes it to
  `scrobbler.played(_:)`; the same number feeds a small `ListenMeter` that fires once per track at the threshold with
  `ListenEvent(songID:, title:, artist:, context:, full:)`. Previews fire a `sampled` event when they start.
  This doesn't depend on Last.fm being connected, and Last.fm scrobbling is untouched.
- The passport turns events into album marks: with context `.album(id)`, count distinct song IDs against
  `catalog.json`'s `trackCount`. With any other context, a track counts toward an album if its Apple Music album ID
  matches a `collectionId` in `catalog.json`.
- When the queue runs out after an album context, the player posts "finished album X", which the UI uses to offer the
  three doors.

### `Shared/Model/Recommender.swift`

```swift
struct Door { enum Kind { case sameRoom, whatNext, echoToday }; let kind: Kind; let album: Album; let because: String }
func doors(after album: Album, library: JazzLibrary, passport: Passport) -> [Door]
```

- **Same room**: the album sharing the most credited players with this one, excluding the same leader. Before 1.1's
  data exists for an album: the leader's strongest connection's top record. `because`: "Paul Chambers and Jimmy Cobb
  are the rhythm section here too."
- **What happened next**: an album from an era in `leadsTo`, closest in year after this one, starter picks first.
  `because`: the destination era's tagline.
- **An echo today**: walk the ties outward from the leader until reaching artists whose primary era is post-bop or
  contemporary; take their record. Fallback: same instrument family, contemporary. `because`: names the link.

All three skip heard records when an unheard one qualifies, and never repeat each other. Pure function, fully tested.

### Last.fm import

`user.getTopAlbums` (the user's name is already stored after connecting), up to 500 albums, matched to the Crate by
normalized artist and title, the way `ITunes.norm` does. Matches are shown as a list to confirm before anything is
marked. Read-only; needs no new permission.

## Tests

- Merge: both orders give the same result; a clear after a mark wins; a later mark after a clear wins; unknown keys
  from a newer version survive a round trip.
- Heard threshold: 60% of tracks, each over its own threshold; repeats of one track don't count twice; previews only

## Risks

- **Mac signing for iCloud** (package 5) is the one unknown; it has a fallback and its own package.
- **Marking by mistake**: leaving an album playing shouldn't feel like cheating or like surveillance. Heard is always
  undoable, and Settings has *Erase Passport*.
- **MusicKit album IDs**: matching a playing song back to a Crate album relies on the song's album ID equalling
  `catalog.json`'s `collectionId`. They're the same ID space (the app already plays albums by that ID), but reissues
  can differ. The `.album(id)` context covers the common case regardless.
