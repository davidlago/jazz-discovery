# 1.1 — Sessions & Sidemen

*Released as 1.1.0 on 2026-11-18. As built: 86 of 88 albums reviewed (two still drafts, no source for their players);
41 sidemen; 104 bonds, 9 hand-picked connections dropped as unsupported; the path finder link is
`between/<artist>/<artist>`.*

*Kind of Blue* prints its band on the cover, but the app doesn't know John Coltrane is on it. This release teaches the
data who played on every record, and builds on that three ways: sidemen become people you can follow, Connections
lines say why they exist, and you can ask for the path between any two artists.

It's first because 1.2 (recommendations), 1.5 (where records were made), 1.6 (instruments) and 1.8 (session
anniversaries) all read what it adds.

## What people get

- **Personnel on every album page**, set like back-cover liner credits, with who sat out which track, when and where
  it was recorded, and who produced and engineered it.
- **Sidemen as artists.** Around 40 new people who never led a record in the Crate but are all over it: bassists,
  drummers, and the first trombone and vibraphone players in the app.
- **"Also plays on"** on artist pages: records they're on but didn't lead.
- **Played With, with reasons**: "5 records together", and which.
- **Connections that mean something**: a line's weight is how many records two people share; selecting a line or a
  face lists them.
- **Path finder**: pick two artists and see the shortest chain of shared records between them, playable as a queue.

## Data

### `ids.json` (new, generated)

`scripts/build-ids.py` looks up each artist's Wikipedia title (already in `jazz.json`) on Wikidata and writes:

```json
{
  "miles-davis": {
    "wikidata": "Q93341",
    "musicbrainz": "561d854a-6a28-4aa7-8c99-323e6ce46c2a",
    "born": "1926-05-26",
    "died": "1991-09-28"
  }
}
```

The MusicBrainz ID is what lets the sessions script match a credited player to one of our artists without guessing
from names. The exact dates aren't shown until 1.8, but they come for free here. The validator checks that the year in
`ids.json` agrees with `born` and `died` in `jazz.json` and reports any that don't, which is also a free audit of the
existing data.

### `sessions.json` (new, drafted by script, reviewed by hand)

One entry per album ID:

```json
{
  "kind-of-blue": {
    "reviewed": true,
    "source": "musicbrainz:release/49234de2-790c-46e5-b780-3cd6be79a2db",
    "recorded": [
      { "date": "1959-03-02", "place": "CBS 30th Street Studio", "mbPlace": "…" },
      { "date": "1959-04-22", "place": "CBS 30th Street Studio", "mbPlace": "…" }
    ],
    "personnel": [
      { "artist": "miles-davis", "name": "Miles Davis", "instruments": ["trumpet"] },
      { "artist": "john-coltrane", "name": "John Coltrane", "instruments": ["tenor saxophone"] },
      { "artist": "cannonball-adderley", "name": "Cannonball Adderley", "instruments": ["alto saxophone"],
        "except": ["Blue in Green"] },
      { "artist": "bill-evans", "name": "Bill Evans", "instruments": ["piano"] },
      { "artist": "paul-chambers", "name": "Paul Chambers", "instruments": ["bass"] },
      { "artist": null, "name": "Jimmy Cobb", "instruments": ["drums"] }
    ],
    "crew": [
      { "name": "Irving Townsend", "role": "producer" },
      { "name": "Fred Plaut", "role": "engineer" }
    ]
  }
}
```

(Values above are what MusicBrainz returned for the album's first release on 2026-11-17, shortened; the review pass is
where the rest, such as the pianist on "Freddie Freeloader", gets confirmed. `paul-chambers` stands for one of the
sidemen this release adds; Jimmy Cobb shows what a player without a page looks like.)

Rules:

- `artist` is one of our artist IDs, or `null` for someone who has no page. People with no page are shown as plain
  names.
- `only` / `except` list track titles when someone isn't on the whole record. Absent means all tracks.
- `instruments` use the app's vocabulary, not MusicBrainz's ("double bass" → "bass", "drums (drum set)" → "drums").
  The script holds the mapping, and a second map from instrument to the family used in filters (tenor saxophone →
  Saxophone).
- `reviewed: false` entries are kept in the file and ignored by the app.
- **Compilations** (most of the 13 albums dated before 1950: the Hot Fives and Sevens, *The Essential Bessie Smith*,
  the Savoy and Dial master takes) span many sessions. They get `"kind": "compilation"`, a `recordedBetween: [1925, 1928]` range, and
  only the players who recur across the set, each with a `tracks` count. The album page says "Recorded 1925–1928
  across many sessions" instead of pretending there was one band.

### `scripts/build-sessions.py`

For each album without a reviewed entry:

1. Find the release group on MusicBrainz: by the leader's MusicBrainz ID (from `ids.json`) and the title, preferring
   the one whose first release year matches `album.year`. A small `overrides` map at the top of the script pins the
   ones that still match wrongly.
2. Fetch up to five editions, earliest first, with recording-level relationships, and keep the edition with the most
   credited tracks whose track count is closest to the Apple Music match in `catalog.json`.
3. Collapse per-track credits into `personnel` with `only`/`except`, map instruments, match players to our artists by
   MusicBrainz ID, collect dates and places, producer and engineer.
4. Write the entry with `reviewed: false` and print a one-screen summary per album for review.

It sleeps a second between requests, retries 503s with backoff, saves after every album and skips reviewed entries, so
it can be stopped and rerun. A full run is about 90 albums × 7 requests ≈ 15 minutes.

Review is by reading: for each album, compare the summary with the album's Wikipedia page or liner notes, fix, set
`reviewed: true`. Where MusicBrainz has nothing (expect a handful, mostly recent records), the entry is written by
hand from the liner notes and the `source` says so.

### `jazz.json` changes

- **New artists**: anyone who appears on three or more curated records, or fills an instrument the app lacks, gets an
  entry. The script prints the candidates ranked by appearances; the list is whatever the data says, then your call.
  Sidemen entries are ordinary artists (blurb, eras, Wikipedia title, signature tracks) with `"albums": []`.
- **`bonds`** (new top-level list) for relationships that aren't "played on the same record":

  ```json
  { "a": "louis-armstrong", "b": "king-oliver", "kind": "mentor", "note": "Oliver gave the young Armstrong his first cornet lessons and later sent for him from Chicago." }
  ```

  `kind` is `mentor`, `band`, `influence` or `duo`. Each existing `connections` pair that the sessions data doesn't
  explain needs either a bond with a note or removal; the validator lists them.
- `Artist.connections` stays as the curated list. The graph the app draws becomes: curated connections ∪ bonds ∪
  pairs who share a record.

### Validator additions

Every `artist` in `sessions.json` exists; `only`/`except` titles exist in the album's tracklist (once
`tracklists.json` exists, 1.3; until then, a warning); dates parse; reviewed entries have at least one player; every
curated connection is explained by a shared record or a bond.

## Shared code

`Shared/Model/Models.swift`

```swift
struct Credit: Codable, Hashable { let artist: String?; let name: String; let instruments: [String]
                                   let only: [String]?; let except: [String]?; let tracks: Int? }
struct RecordingDate: Codable, Hashable { let date: String; let place: String?; let mbPlace: String? }
struct Session: Codable { let reviewed: Bool; let kind: String?; let recorded: [RecordingDate]?
                         let recordedBetween: [Int]?; let personnel: [Credit]; let crew: [CrewCredit]? }
struct Bond: Codable, Hashable { let a: String; let b: String; let kind: String; let note: String }
```

`Shared/Model/JazzLibrary.swift`

```swift
func session(for albumID: String) -> Session?            // reviewed only
func appearances(of artistID: String) -> [Album]         // on the record, not the leader
func sharedAlbums(_ a: String, _ b: String) -> [Album]
func tie(_ a: String, _ b: String) -> Tie?               // shared albums + bond, for "why are they connected"
var ties: [Tie]                                          // replaces `edges`; each has a weight
func path(from a: String, to b: String) -> [PathStep]?   // shortest chain; each step names the linking album or bond
func instruments(of artistID: String) -> [String]        // from credits, most frequent first
```

`path` is Dijkstra over ties with cost `1 / (1 + sharedAlbums)`, so it prefers strong links over a single shared
session; ties with only a bond cost 1. `GraphLayout.compute` takes weighted edges and uses the weight as spring
strength, which pulls working bands together.

With around 130 artists the graph has many more lines than today's 165. Drawing rule: at rest, show bonds and ties of
two or more shared records; when an artist is selected, show all of theirs.

Groundwork that lands here (see the roadmap README): the test target, the single `Route`, the shared link parser with
the Mac's URL scheme, optional data files.

## Mac

- **`AlbumDetailView`** (`JazzDiscovery/Views/AlbumViews.swift`): a **Personnel** section between "why it matters" and
  the tracklist. Two columns of liner credits; names with pages are links in the era tint; "except *Blue in Green*" in
  muted italics. Under it one line: *Recorded March 2 and April 22, 1959 · CBS 30th Street Studio · Produced by Irving
  Townsend*. In the tracklist, hovering a track dims the players who aren't on it.
- **`ArtistDetailView`**: "Also Plays On" row of album cards after their own records, each captioned with the
  instrument. "Played With" cards gain a caption ("5 records" or the bond's kind) and sort by weight.
- **`ArtistsView`**: a *Leaders / Sidemen / Everyone* segmented control (a sideman is an artist who leads no curated
  album); the instrument picker lists what the credits say, grouped by family.
- **`ConnectionsView`**: line width from weight; clicking a line, or a second face while one is pinned, fills
  `SelectedArtistPanel` with "Miles Davis × John Coltrane — 4 records" and the covers. A **Find a Path** button in the
  toolbar opens two artist pickers; the result highlights the chain on the map and lists it in the panel, with *Play
  the Path* (one starred track from each linking record).
- **Search**: also matches people who appear only in credits, and lists the records they're on.

## iPhone

- **`AlbumDetailView`** (`CrateTab.swift`): the same Personnel block, one column; long bands collapse to the first
  eight with *Show all*.
- **`ArtistDetailView`** (`ArtistsTab.swift`): "Also Plays On"; captions on "Played With".
- **`ArtistsTab`**: the Leaders / Sidemen / Everyone filter chip row.
- **`ConnectionsMapView`**: tapping a second face while one is selected shows the tie card; a **Path** button next to
  the fit-to-screen button opens the pickers as a sheet with search. The result zooms the map to the chain and shows
  it as a horizontal strip of faces joined by small covers.
- **Links**: `jazzdiscovery://between/<artist>/<artist>` (`path/…` is kept free for 1.7's journeys).

## Tests

- `sharedAlbums`, `appearances` and `instruments` on a small fixture library.
- `path`: finds the direct tie, prefers the heavier of two routes, returns `nil` across disconnected artists, is
  symmetric.
- Decoding: a `sessions.json` with unknown fields and with missing optional fields still loads; unreviewed entries are
  invisible.
- The link parser: every link in the README resolves to the same page as before; unknown IDs resolve to nothing.

## Risks

- **MusicBrainz coverage is uneven** (see the roadmap README). Mitigation is built in: review everything, hand-write
  the gaps, hide what isn't reviewed.
- **Compilations** don't fit the one-band model; they're handled as a separate kind, not forced.
- **A denser graph** could turn Connections into a hairball. The at-rest drawing rule above is the first defence; if
  it's still busy, raise the threshold to three shared records.
- **Scope of the sidemen list**: forty blurbs is real writing. Package 6 can ship twenty and grow.

## Done when

The common checklist in the roadmap README, plus: every album page either shows reviewed personnel or nothing; every
line on the Connections map can say why it's there; the path finder returns a chain for Scott Joplin → Nubya Garcia or
says plainly that there isn't one.
