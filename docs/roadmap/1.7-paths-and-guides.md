# 1.7 — Paths & Listening Guides

*Released as 1.7.0 on 2026-11-18, with Paths only. As built:*

- *Seven paths: Start Here (its stops come from the starter picks, so the two can't disagree), Jazz for People Who
  Think They Hate Jazz, 1959, Late Night, The Latin Tinge, One Tune Five Decades, The Piano Trio. Hip-hop sampling,
  protest and London paths wait for sources to be noted on each claim.*
- *Progress lives in the passport (`paths`, and `songsHeard` for track stops) and merges like the rest. Album stops
  count when the record is heard; track stops when the song plays through; reading stops when opened from the path;
  any stop can be ticked by hand. Since 1.10 the player knows the path stop it's playing (`PlayerController.pathStop`,
  set by `PathPlayback`) and offers the next stop not yet done; Siri, Shortcuts and the Continue widget can play the
  next stop too.*
- *Listening guides are not in this release. Their timings have to come from someone listening with the editor; the
  format, `FormBar`, guide page and Mac editor described below are still the plan, and need a session at the
  keyboard with headphones.*

The two features that make the app a teacher. **Paths** are journeys with a point of view: a handful of stops, each
with something to listen for. **Listening guides** follow a recording as it plays, showing its form as a diagram and
telling you what's happening now.

Needs 1.3 (bundled tracks) and 1.6 (playing from a time; the glossary terms the notes use). Paths alone need only 1.3.

## What people get

- **About ten paths** beside Start Here: by mood, by idea, by way in.
- **A path page** you can follow over days: numbered stops, your place kept, a stamp when you finish.
- **Listening guides for about a dozen recordings**: a **form bar** showing the head, each solo and the way out, with
  a playhead; notes that change as the music moves; tap any section to jump there.
- The guide appears in the player whenever a guided recording is playing, the way lyrics do in Music.
- Glossary examples jump to the exact passage.

## Paths

### `paths.json` (new, hand-written)

```json
{
  "paths": [
    {
      "id": "nineteen-fifty-nine",
      "title": "1959",
      "subtitle": "The year jazz went five directions at once",
      "tint": "#7A5CD6",
      "intro": "A paragraph on the idea of the path.",
      "minutes": 210,
      "stops": [
        { "kind": "album", "ref": "kind-of-blue", "note": "What to listen for at this stop, two or three sentences.",
          "start": { "title": "So What", "artist": "Miles Davis" } },
        { "kind": "track", "track": { "title": "…", "artist": "…", "year": 1959 }, "note": "…" },
        { "kind": "tune", "ref": "body-and-soul", "note": "…" },
        { "kind": "term", "ref": "modal", "note": "…" }
      ],
      "outro": "Where to go from here.",
      "next": ["free-and-after"]
    }
  ]
}
```

A stop is an album, a track, a tune (1.4), a term (1.6), an era, an artist or a place (1.5). Album stops name the
track to start with. Kinds from releases that haven't shipped are simply not used yet.

**Start Here** becomes the path `start-here`, written out as stops with notes. `album.starter` stays in `jazz.json`
for the Crate filter; the validator checks the two agree.

### Shared code

```swift
struct JourneyPath: Codable, Identifiable { … }     // "Path" would collide with SwiftUI's
struct Stop: Codable, Hashable, Identifiable { … }

extension JazzLibrary { var paths: [JourneyPath]; func path(_ id: String) -> JourneyPath? }
extension Passport {
    func progress(on path: JourneyPath) -> (done: Set<Int>, next: Int?)
    func complete(stop: Int, of path: JourneyPath)     // also set automatically from ListenEvents
}
```

A stop completes when its music counts as heard (the 1.2 rule) with `PlayContext.path(id, step)`, when its album is
already heard, or by hand. Term, era and place stops complete when opened.

### Views (both apps)

- **Path index** (Mac sidebar **Paths** in Listen; iPhone Discover row and page): poster cards in each path's tint
  with the title in display type, stop count, running time, and a progress ring once started.
- **Path page**: the intro, then the **route**: a vertical line in the path's tint with numbered stops (the Start
  Here numerals). Each stop shows its artwork or portrait, title, the note, and a play button; done stops are stamped;
  the next stop is expanded and has the page's main *Continue* button. The outro and "next paths" at the end.
  Finishing a path adds a path stamp to the Passport page, in a second sheet under the era stamps.
- **Discover**: the Start Here row becomes **Paths**, led by the path you're on ("Continue: 1959 · stop 3 of 5"), then
  suggestions; new users see Start Here first.
- **Now playing**: with a path context, the stop's note is the "why this track" line, and *Next Stop* appears when
  the stop's music ends.
- **Links**: `jazzdiscovery://path/<id>`, `paths` (1.1's artist-to-artist chain is `between/…`, so the two don't
  collide).

## Listening guides

### `guides.json` (new; prose by hand, timings from the editor)

```json
{
  "guides": [
    {
      "id": "so-what",
      "track": { "title": "So What", "artist": "Miles Davis", "year": 1959 },
      "songID": 0,
      "duration": 0,
      "album": "kind-of-blue",
      "tune": "so-what",
      "intro": "What makes this recording worth nine minutes of attention.",
      "form": "AABA, 32 bars; each soloist takes two choruses",
      "sections": [
        { "at": 0,   "kind": "intro", "label": "Prelude", "who": ["bill-evans", "paul-chambers"], "note": "…" },
        { "at": 0,   "kind": "head",  "label": "The theme", "who": ["paul-chambers"], "note": "…", "terms": ["call-and-response"] },
        { "at": 0,   "kind": "solo",  "label": "Miles Davis", "who": ["miles-davis"], "note": "…", "terms": ["modal"] }
      ]
    }
  ]
}
```

(The times above are placeholders. Real ones come from listening.)

- `kind`: `intro`, `head`, `solo`, `trading`, `interlude`, `vamp`, `head-out`, `coda`. The kind sets the block's
  shade in the form bar; a solo's colour comes from the soloist.
- `who` are artist IDs (from 1.1's personnel) or names.
- `songID` and `duration` pin the guide to one Apple Music recording. Timings are only true for that recording.
- Optional `marks` inside a section: `{ "at": 0, "note": "the quote from …" }` for a single moment.

### Pinning and syncing

- A guide is offered when the playing song's ID equals `songID`, or when its title and artist match and its duration
  is within two seconds of `duration` (another edition of the same master). Otherwise the guide is readable but not
  synced, and says "Timings are for another edition".
- With previews there's no way to know where in the track a 30-second clip sits, so the guide is readable, marks which
  section a preview probably falls in only if that's been noted by hand, and offers *Open in Music*. This is the one
  feature in the roadmap that really wants a subscription; the page says so plainly.
- The player's tick is every 400 ms, fine for notes that change every 20 seconds but jumpy for a moving playhead. The
  form bar animates between ticks using the last known position and play state, and resyncs on each tick.
- `player.seek(toSeconds:)` (new; the existing `seek(to:)` takes a fraction).

### The guide editor (Mac, in the Debug menu)

Timings can't be written from memory or generated; someone has to listen. The editor makes that fast:

- Open it on any playing track. Space plays and pauses; **M** drops a section marker at the current time; ←/→ nudge
  the selected marker by half a second; ⇧←/⇧→ replay the two seconds around it.
- Each marker gets a kind, a label, who, and a note, in a table beside the waveform-less timeline (a plain bar; no
  audio analysis is available through MusicKit).
- It saves `guides.json` entries with the current song's ID and duration filled in, to a file you choose (the app is
  sandboxed, so through a save panel).
- The same editor sets `at`/`until` on glossary examples (1.6).

The workflow: Claude drafts each guide's structure and notes from the recording's well-documented form (who solos in
what order, how many choruses); you play the track once in the editor and tap the markers in; we read the notes
against the music and fix what doesn't match.

### Views

- **`FormBar`** (`Shared/Design/FormBar.swift`, both apps): the whole track as a horizontal bar of blocks, widths by
  duration. Heads in cream, solos in the soloist's era tint with their initials, trading as stripes of the two
  players' colours. A playhead line moves across; tapping a block jumps to it; marks are small ticks. Under Reduce
  Motion the playhead steps instead of gliding. VoiceOver reads it as a list of sections with times.
- **Guide page** (Mac: opens from a track row's guide badge, from the player, and from an index under Listen; iPhone:
  a page, and a mode of Now Playing): the intro and form line; the form bar pinned at the top; below it the current
  section's label, who (portraits), and note, large, with previous and next sections dimmed above and below, scrolling
  as the music moves. Glossary terms in notes are tappable (1.6's `TermText`).
- **Now playing**: a **Guide** button appears when the current track has one. On iPhone it switches Now Playing's
  lower half to the guide, as the lyrics button does in Music. On the Mac it opens the guide as a panel above
  `NowPlayingBar`.
- **Track rows**: a small form-bar glyph marks guided tracks on album, era and tune pages.
- **Paths**: a stop can point at a guide; the How to Listen primer does.
- **Links**: `jazzdiscovery://guide/<id>`.

## Tests

- `section(at:)`: boundaries, before the first section, after the last, zero-length guards.
- Pinning: exact ID syncs; same title within two seconds syncs; a live version of the same tune doesn't.
- Interpolation never runs ahead of the track's end and stops when paused.
- Path progress: listening marks a stop; an already-heard album counts; un-marking works; the path completes only when
  every stop has.
- `start-here` in `paths.json` and `album.starter` agree.

## Risks

- **Timing is manual and per edition.** A remaster swap on Apple Music can change a song ID. The duration fallback
  covers most cases; the validator can re-check each `songID` still resolves (one lookup per guide) before a release.
- **Guides don't work on previews.** Stated plainly in the app; paths, radio and everything else still do.
- **Mac MusicKit seeking** is already used by the scrubber, so jumping to a section should behave; excerpt end times
  are the less certain part and are 1.6's risk.
- **Writing quality.** A guide that says "listen to the wonderful solo" teaches nothing. Each note should name
  something you can hear and check: who enters, what the bass does, where the tune comes back. That's the review
  standard.
- **Sample and protest claims** in paths need sources, like every other fact.

## Done when

The common checklist, plus: on a guided track with Apple Music connected, the note on screen always describes what's
playing within two seconds, from start to finish, and after a jump; the same track on previews shows the guide
unsynced and says why; Start Here keeps your place across both devices.
